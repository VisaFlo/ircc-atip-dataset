              Chinook 1.5 Module 3 at a Glance

              The TRV Journey Lab has worked with external consultants to develop Chinook 1.5 Module 3.




              This new version of Chinook is based in Microsoft's Dynamics 365 software that is accessed via a browser.
              This platform was chosen for stability, IT security and flexibility. The Lab includes a development team that is
              releasing updated versions of Chinook on a bi-weekly schedule. Enhancements and bug fixes will be based
              directly on user feedback and added to the Journey Lab's backlog of tasks.

              This "iterative" approach means that while initial releases




              The User Interface (UI) in Chinook 1.5 differs from what users will be familiar with from Excel, though it aims
              to remain faithful to the officer-centric principals that guided the design of the original Chinook. Multiple
              files, data points and fields can be viewed on a single screen and the number of clicks required to take an
              action have been minimized to the extent possible. Officer input will be essential for improving the UI and
              User Experience (UX) following the initial roll-out.

              A significant change in Chinook 1.5 is the way that a user accesses files. This no longer requires a manual
              upload into the tool; Chinook 1.5 will be updated centrally and will eventually include all open TR applications
              (with the exception of Visitor Records). Officers can simply paste in the applications they have been assigned
              (or assigned to themselves) and begin processing.

              Note that Chinook 1.5 still does not have a direct connection to GCMS and files are not updated in real time.
              Thus, though files can be assigned to users and offices and numerous different tasks actioned in Chinook 1.5
              these will not be reflected in GCMS until they are pasted into GCMS using the process outlined in this
              manual.

              Chinook 1.5 builds on the most recent version of Chinook in Excel (Chinook+) which added new features in
              Chinook and GCMS to help improve the decision-maker experience while processing TR applications.

              Several features have been built to create a link between Chinook and GCMS, which allow decision-makers
              to:

              1. Automate Final Decision Administrative tasks:
                    Using the new tools, decision-makers can now automate tasks that were previously done manually such
                    as:

                          •   Final Decision entry
                          •   Pasting notes from Chinook into Notes Tab
                          •   Entry of refusal grounds
                          •   Generation and sending of passport request/refusal letters

             6. Exporting to GCMS

               Decisions and Actions must be exported to GCMS via the Applications Ready For GCMS view and
               Send to GCMS button. Once clicked, the button will copy instructions for GCMS onto your clipboard
               that can then be pasted directly into the GCMS Chinook Tab to perform final decision administrative
               actions that typically would have been done manually. These actions are the following (See Annex B
               & C for full details of actions completed in GCMS, including logic):

                   o   Final Decision entry
                   o   Biometrics FCC Detail Assessments
                   o   Pasting decision notes from Chinook into Notes Tab
                   o   Entry of refusal grounds
                   o   Generation and sending of passport request/refusal letters
                   o   Generating counterfoils and Permit documents
                   o   Setting Counterfoil Print Queue
                   o   Setting Counterfoil Validity Date
                   o   Setting Permit Validity Date (SP/WP/SP-EXT/WP-EXT only)
                   o   Setting Conditions & Remarks (SP/WP/SP-EXT /WP-EXT only)
                   o   Setting Exit by Date
                   o   Updating Number of Entries
                   o   Updating NOC Code and Exemption Code
                   o   Assigning Application with the Due date

What is the Decision Maker Module?
The Decision Maker Module is a tool that aims to increasing the quantity of decisions that an officer can
make on any given day as well as improve the quality of those decisions. Increased efficiency is gained
by bringing a range of pertinent information required for making decisions together in one place where
it can be reviewed easily and effectively. The DMM is organized in such a way that efficiencies of scale
can be produced by processing like cases together and facilitating grouping in the finalization process.




Using the Decision Maker Module


For best results we suggest you organize workstation so that you have one monitor in a landscape
orientation (to be used with Chinook) and your other in Portrait (to be used for GCMS).

   What is Module 3 - Decision Maker Module?
    The Module 3 - Decision Maker Module is a tool that aims to increase the quantity of decisions that an officer
    can make on any given day as well as improve the quality of those decisions. Increased efficiency is gained by
    bringing a range of pertinent information required for making decisions together in one place where it can be
    reviewed easily and effectively. Module 3 is organized in such a way that efficiencies of scale can be produced
    by processing like cases together and facilitating grouping in the finalization process.

  In order to submit a new set of indicators for inclusion in Chinook Module 5, you must complete
  the attached submission template.

  indicator database for use across IRCC.




  How to Complete the Form

  IRCC Office Name: Select from the dropdown to match Chinook Module 5 Source List.

  Summary of Submission: Indicate here a brief summary of the submission, including how it was
  encountered. This is your opportunity to explain why this indicator set should be included in
  Module 5.

  Source: Select from the dropdown to match Chinook Module 5 Source List.

  Rule Origin: Select from the dropdown to match Chinook Module 5 Source List.

  Rule Type: Select from the dropdown to match Chinook Module 5 Source List.

  Criteria: Indicate the criteria/filters that will be used to identify the applications/clients which will
  be filtered for in Chinook.

  Ex.      Client COB equals

           Employer CONTAINS "Engineer"

           DLI does NOT equal University of Ottawa

  Please be precise and try to ensure your criteria do not capture too wide of a group. Ensure you
  select criteria only from one module OR the other. You cannot combine criteria from Mod 1 and
  Mod3.

  You can use equals (==), does not equal (!=), or contains (-=)

  Validity Period: 4 months is the default period for an indicator set to be included. Only provide
  justification if anything other than 4 months is required.
